# 从利益演示表图片计算收益

## 识别与核对

使用宿主 AI 的图片查看/视觉工具按原始分辨率查看用户上传的图片。OCR 可辅助，但关键数字须与原图复核；不要上传图片到外部 OCR 服务，除非用户明确授权。图片不是脚本输入：先形成事实表和 JSON，再调用计算器。

先识别产品名称、方案、表头、单位、缴费频率、每期保费、缴费期限，以及“保单年度末/年初/年龄”的行含义。只提取计算所需字段，不抄录姓名、证件号等个人信息。多张图按产品、方案及保单年度拼接；重叠行去重、矛盾值标为待确认，不能混合不同方案或演示档位。

特别核对：

- “年度保费”与“累计已交保费”不能互换；元、万元、每千元保费对应利益要明确换算。不能仅凭累计保费一格反推整段缴费安排。
- “基本保额、身故保险金、疾病给付”不是退保可取得金额。计算持有/退保收益使用目标年度对应的现金价值或明确的退保总利益。
- 保证现金价值与非保证红利分开；“演示总利益”若已包含保证价值，不能再次相加。只有表头/注释明确包含关系时才能从组成项合计。红利购买增额保险时，新增保额不等于可退保的红利现金价值。
- 现金领取的红利/生存金用实际时点正现金流计算。累计领取额不能和已经包含它的总利益重复计算，也不能将全部领取额挪到期末。仅有累计值、缺少领取时点时，保留缺口，不能计算精确 XIRR。
- “年末第10年”与“年龄50岁”不同，不根据年龄差猜保单年度。缺年度映射时请求必要说明。
- 模糊数字、截断表头、破折号或空格标为“未显示/待确认”，不能填成0。只显示保证或演示口径时仅算这一口径；若0确实清晰显示，允许填0并报告无可用年化。

可继续的字段先提取，无需例行要求用户确认整张表。只有关键缺口影响结果时，集中提出一个简短问题或要求清晰补图。记录原始文本、归一金额、图号/文件名、行、列及换算规则到顶层 `provenance`，未知值留在缺口记录中，不传入数值字段。

## 按年末利益计算

等额年初缴费、各行是年度末退保利益、无中途领取时，使用 `insurance-table`。用户指定年度只取对应行；未指定时计算图片中能明确读出的全部年度，缺失行不插值、不外推。

必填：

- `annualPremium`：等额年缴保费。
- `paymentYears`：计划缴费年数，趸缴填1。
- `premiumTiming: "year-start"`：已确认或明确披露的年初缴费模型。有月缴、年末缴费等安排时改用 `xirr`，不能套年初模型。
- `timeBasis`：有真实首笔缴费日期时选择 `actual-dates` 并填 `startDate`；没有日期时选择 `policy-years`，每年按365天计算模型 IRR。不要伪造保单起始日期，也不用当前日期代替。
- `rows`：每行含正整数 `policyYear`，以及至少一项 `guaranteedValue` 或 `illustratedValue`。缺失口径省略字段，不填 null/0。每一项是该年末可取得的退保金额，须与表头相符。

以下是假设数据，用于理解接口，不是从真实图片识别的结果：

```json
{
  "action": "insurance-table",
  "provenance": {
    "source": "用户上传图片",
    "files": ["利益演示表.png"],
    "unit": "元",
    "fields": [
      {"field": "annualPremium", "image": 1, "location": "页首年交保费", "raw": "10,000"},
      {"field": "rows[1].guaranteedValue", "image": 1, "location": "第5年末/保证现金价值", "raw": "32,000"}
    ],
    "gaps": ["未显示首笔缴费日期，第1年未显示非保证口径"]
  },
  "input": {
    "annualPremium": 10000,
    "paymentYears": 3,
    "premiumTiming": "year-start",
    "timeBasis": "policy-years",
    "rows": [
      {"policyYear": 1, "guaranteedValue": 6000},
      {"policyYear": 5, "guaranteedValue": 32000, "illustratedValue": 35000},
      {"policyYear": 10, "guaranteedValue": 38000, "illustratedValue": 45000}
    ]
  }
}
```

优先运行 `python3 <skill目录>/scripts/calculate.py <识别结果.json>`；只有 Node 时可改用 `node <skill目录>/scripts/calculate.mjs <识别结果.json>`。引擎以各年初保费为负现金流，以每个所选年末退保利益为正现金流，分别求保证与演示收益。第1年末退保只计第1次保费，不能先扣整个3年计划保费。输出 `paidPremium` 是该年实际已缴总额，`totalPlannedPremium` 是完整计划总额，二者不能混淆。

`actual-dates` 模式按周年日计算 XIRR，2月29日在非闰年的周年日按2月28日；`policy-years` 模式输出年序号现金流，年化标为“年度模型 IRR”。若周年日约定不同，使用明确日期的 `xirr`。两种模式都保留终值、累计收益与现金流；无解时年化为 null，附 error，不能展示为0%。

## 非规则现金流与交付

有月缴、不等额缴费、中途领取或已领取红利时，按实际日期分别构建保证/演示 `xirr` 请求；只有保单年序时可用显式披露的365天年度模型构建时间轴，但必须标注模型 IRR，不称实际日期 XIRR。不要为了满足简化接口忽略现金流。

交付时先展示关键提取值（缴费、年度、退保价值、原图定位及单位），再列各年度已缴保费、保证退保金额/收益/年化、演示退保金额/收益/年化。只有已确认列才输出数值，另一列标“未显示”。说明年度时点、日期口径和未覆盖信息；非保证列始终带“演示”标签。换一个期限须取对应行，不能沿用上一行的终值。

图片识别不等于利益表真实性或合同核验；不要称已核实合同保证条件，除非用户提供的材料足以支持该结论。

可复用的客户问答、双口径结果表及第1年提前退保示例见 [examples.md](examples.md) 案例四。利益演示表不属于基金历史总回报序列，不能直接计算夏普或据其年度终值变化宣称市场最大回撤。
